# 设计方向

方向决定“为什么这样设计”，不是选一套好看的样式。先定方向，再画；方向错了，后面所有细节都在给错误骨架抛光。

## 1. 产品事实

写下：用户、品牌、核心任务、真实内容与数据、主设备/视口、已有设计系统、素材与技术限制。缺的标未知，不拿参考产品的内容当自己的事实。

先认品类，再看该品类一线产品怎样建立用户已经期待的结构；这是基线，不是抄袭对象。

## 2. 参考分开拆

产品参考和交互参考分开：

- **产品参考**：首屏有什么、内容怎样组织、视觉身份怎样成立。至少看两家真实画面，拆 6–10 条“是什么样、为什么这样做”。
- **交互参考**：核心动作的“触发 → 对象变化 → 反馈 → 下一状态”，以及关键状态。不能从产品参考的视觉风格推断交互。
- **借鉴关系，不搬业务**：取“标题最重、图负责情绪、辅助信息很淡”这类关系，用当前产品的内容重组；不复制别人的模块、标志和文案。

## 3. 主角与主动作

每屏写两句：

- 唯一主角是什么？
- 唯一主动作是什么？

有同权重的次要动作、重复解释、无任务贡献的装饰，先合并或降级。再写一条：

`主动作 → 主角/对象变化 → 状态反馈`

确认动作有可见结果。找不到清晰主角/动作，先改结构，不靠视觉救。

## 4. 调性五刻度

从产品事实推出，不用模型默认：

| 刻度 | 两端 | 画面看什么 |
|---|---|---|
| 能量 | 安静 ↔ 喧闹 | 饱和度、对比、元素碰撞 |
| 完成度 | 粗粝 ↔ 精致 | 边缘、对齐公差、颗粒 |
| 密度 | 疏 ↔ 密 | 留白、叠层、网格纪律 |
| 分量 | 轻 ↔ 重 | 字重、色块面积、阴影硬度 |
| 严肃度 | 活泼 ↔ 庄重 | 圆角、插画、动效幅度 |

五个刻度都要写依据；证据指向“安静克制”，就不要交米色卡片 + 柔和阴影的默认答案；证据指向“高密度工具”，就不要为了留白删必要信息。

## 5. 模糊词必须翻译

| 模糊词 | 翻译成 |
|---|---|
| 高级 | 哪一种高级；字体对比、分隔方式、间距尺度、色相数量 |
| 精致 | 字距、对齐到几像素、阴影最多几层、色相最多几种 |
| 克制 | 强调色面积上限、动效幅度上限、色相数量上限 |
| 史诗 | 展示字多大、主图占比、明暗对比多强 |
| 简洁 | 密度档位、删掉什么、为什么删 |
| 粗糙 | 错位多少像素、旋转多少度、哪些边缘故意不齐 |

翻译不出可观察决定的词，从理由里删掉。

## 6. 方向卡

只做一个推荐方向时，用 4–6 行写清：

- 给人什么感觉；
- 首屏长什么样；
- 核心动作怎样完成；
- 字体 / 色彩 / 主视觉 / 图标语法；
- 记忆点；
- 主动放弃什么。

详细版写进 `DESIGN.md`。**默认只推荐一个**，用户确认后只深化这一个；用户明确要求比较时才做 2–3 个首屏。

## 7. 差异检验

做多方向时，骨架、字体、色彩关系、主视觉四项，任意两个方向最多只能有一项相同。否则不是不同方向，是同一模板换色。

首屏缩到 480px 宽并排看一次；遮住产品名再问：如果换成无关产品还原样成立，说明只是品类模板，不是这个产品的设计。

## 8. 反模型默认

出现这些信号时重新审视，不自动禁止，但必须有产品理由：

- 深色底 + 紫蓝弥散光 + 玻璃卡片；
- 每张卡片都渐变、重阴影、不同强调色；
- 所有按钮都是胶囊、所有圆角都 16px；
- 每个方向都用 Lucide/Heroicons 同一种图标；
- 落地页固定“主视觉 + 三特性 + 评价 + CTA”；
- 后台固定“侧栏 + 指标卡 + 折线 + 表格”。

有理由可以用；没理由就是默认。

## 9. 骨架参考

**说服型页面**：首屏用真实交付物/主视觉建立证据，再按“问题 → 能力 → 证据 → 行动”展开。首屏不要只写承诺，最好让用户看到产品实际产出的东西。

**产品工作区**：首屏先定核心对象、当前状态和主动作；主分析、辅助指标、待办、记录有不同分量。工具界面不为了“空旷”砍必要信息，也不把所有信息做成同权重卡片。

**移动端**：内容、导航、主动作比例适当；小空间保留清楚字号层级，不用 9–11px 小字制造精致。

## 10. 记忆点

一页最多一到两处集中发力：一个特别的主视觉、一次有性格的排版、一个和产品对象相关的交互。其余安静、短促。不要每个区块都“设计一下”，最后没有重点。

## 11. 方向过关

- 品类基线在不在？
- 主角/主动作三秒能认出吗？
- 换掉产品名还成立吗？
- 方向卡里的字体、色彩、骨架互相呼应吗？
- 有没有一处只有这个产品才会有的记忆点？

任何一项答不上来，先回方向，不进入细节。
