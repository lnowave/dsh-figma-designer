# 视觉语言

先看焦点、构图、疏密，再调空间、排版、色彩和细节。前一步已经解决问题，就不要为了显得用心继续加样式。

## 焦点与空间

- 每个区域一眼能认出最重要的一条信息或一个动作；其余信息用更小字号、更轻字重、更低对比或靠边退后。
- 同一关系用同一间距；组内紧、组间松。留白用来分组、突出重点、控制节奏，不是均匀撒在各处。
- 没有任务的装饰、重复解释、同权重次要动作先删。
- 区域之间怎么排由父布局管；同一段距离不要由多层样式各加一遍。
- 分隔线/边框不要重复：同一处分隔不叠双线，留白已经分开的地方不补线；线粗细分层级，全页一致。

## 字体与内容

- 固定角色：展示标题、页面标题、正文、辅助信息、标签、数据。角色之间的字号/字重差要够大，角色内部保持一致。
- 用真实产品文案检查字形、字重、回退字体；英文好看不代表中文成立。中英混排看基线、视觉重量。
- 中文正文通常 16–18px 起步；产品界面正文 14–16px；高密度工具 13–14px。正文无单位行高 1.6–1.75；操作文字 14–16px。它们是起点，不是死规定。
- 多行中文标题先用 1.2–1.35 行高，按真实字形看；不照搬英文海报的极紧行高，不把标题高度固定成单行。
- 主动检查断行：行末只剩一两个字、词被拆开、数字/单位被拆行，都算缺陷。`text-wrap: pretty/balance` 只能减少孤字，不能代替检查。
- 重要名称/说明不要用固定高度裁掉；必须截断时给查看完整内容的入口。
- 示例数据要像真的：不整齐的数字、真实时间、长短不一的名字；不要“张三/示例公司/标题/描述/1000 位用户/+10%”。
- 按钮写按下去会发生什么；不写“了解更多/立即开始”这类空话。

### 可读性是交付门槛

在目标视口、实际字体、100% 阅读尺寸下判断。缩略图只看构图。不要靠 9–12px 低对比文字制造精致；信息太多先删冗余、调层级或重排。

## 色彩与表面

- 每种颜色有固定角色：背景、表面、文字、辅助文字、描边、主色、成功/警告/错误。
- 主色面积克制；状态不能只靠颜色区分，还要有文字/图标/形状。
- 表面层级可以靠明暗、色温/色相微偏区分；不要只给每张普通卡片配不同强调色、粗边框、重阴影。
- 边框/阴影/渐变必须服务层级或氛围；没有理由不用。套在容器里的轮廓要和外面协调。
- 在实际背景上看文字、控件边界、焦点、选中态；背景是图片/半透明时尤其要看。
- 对比度：正文至少按项目可访问性要求；没有项目规范时，正文目标 4.5:1，大字/次要信息不低于 3:1。

## 控件与图标

- 控件是一套语法：圆角、描边、字重、阴影、按下位移、选中表达、状态图标，在按钮、输入、标签、开关、空状态之间一致。
- 可点击的东西看得出能点，点了有反馈；默认/按下/聚焦/选中/禁用/处理中样式不同。
- 点击区域不能因为状态变化变小，也不挤动旁边布局；触控目标尽量 ≥44×44。
- 一个产品只用一套图标；描边粗细跟字重走；图标尺寸约为字号的 1–1.25 倍，按视觉中心对齐。
- 陌生图标配可见文字；纯图标按钮要有可访问名称。字符箭头/符号有语义，不为了“统一”把有意义的箭头换掉。
- 品牌图标/插画按真实身份处理，不给每个标题硬配图标。

## 设计系统

- 已有变量/样式/组件优先；没有才建最小集合。
- 不要用“近似值”绕开 token：13px 与 14px、8px 与 10px 的混用会让页面显得廉价。
- 导出代码时，颜色/字号/间距应能追溯到 token；组件实例不应被随手改成散图层。

## 完成前检查

- 100% 与 200% 各看一次；长标题、两行正文、中英混排、数字+单位都看。
- 480px 缩略图做三秒测试：像哪类产品？第一眼看到什么？
- 所有文字块左边缘大致落在 2–3 条垂直锚线上；散成五六处就说明对齐没管。
- 首屏只有一个主角；找不到就重做结构，不靠加装饰。
