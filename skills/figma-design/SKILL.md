# figma-design

操作 Figma 用 `figma-designer` skill（status/read/apply/screenshot/library/...）。本 skill 只负责设计判断、约束和验收，不替代操作层。

## 什么时候用

- 新建页面、重设计、整体改版、做多个视觉方向、评审一个界面是否达标；
- 用户说“做得好看一点”“像真实产品”“帮我评审”“重做这个页面”。

**不用**：改文案、删指定元素、调一个已知间距/颜色、复用现有组件，或用户已经把改法说死。这类直接按 `figma-designer` 做，交付时一句话说明。

## 主流程（按门槛推进）

### 1. 事实与范围

先写清：用户是谁、产品/品牌、核心任务、真实内容、目标设备与主视口、现有设计系统、参考与限制。能读 Figma 就先 `figma_status` + `figma_library` + 当前选区/页面截图；不要凭印象。

只问会改变核心方向且推断不出来的问题；其余自己决定并写明假设。

### 2. 方向卡

先写 `DESIGN.md`（模板见 `references/design-doc-template.md`），至少包含：

- 北极星：一句话，第一感受与全页围绕什么；
- 主角 / 主动作：每屏唯一主角、唯一主动作、动作后的可见结果；
- 调性：能量、完成度、密度、分量、严肃度五个刻度及依据；
- 字体、色彩、间距、圆角/描边、图标语法；
- 页面骨架与状态；
- 记忆点：一到两处集中发力；
- 主动放弃什么。

模糊词必须翻译成可观察决定，例如“高级 → 色相数量、字重对比、间距尺度、阴影层数”；翻译不出就不写。

**默认只做一个方向。** 用户明确要比较时，才做 2–3 个首屏；每个方向必须适配、可落地，不能拿陪跑方案凑数。先看 `references/design-direction.md`。

### 3. 灰度结构

先只做灰阶线框：内容层级、对象、主动作、状态。确认主角和最重信息；结构不通不靠颜色/字体/主视觉遮。

在 Figma 里可以先建灰阶 frame，`figma_screenshot` 后自己看；用户确认方向后再上视觉。用户说“你定/直接做”时不停顿，但仍按这个顺序。

### 4. 设计系统与视觉

- 已有文件：优先复用 `figma_library` 里的组件/变量/样式；没有就用 `figma_variable`/`figma_style` 建最小集合，不要每个节点硬编码。
- 视觉语言、字体角色、中文排版、色彩分工、控件/图标规则见 `references/visual-language.md`。
- 字号/间距/圆角/色彩建议先成 token 再使用；配方见 `references/tokens.md`。
- 真实内容优先：不要 lorem ipsum、“标题/描述/示例数据”；中文按真实字形检查换行、行高、数字单位。
- 避免模型默认：紫蓝弥散光、玻璃卡片、千篇一律的 SaaS 卡片墙、同一套 Lucide 图标、无理由的渐变和阴影。

### 5. 真实画面证据

- 用 `figma_audit` 先跑一遍客观检查（对比度/字号/行高/占位/点击区/间距/token/裁剪），按 `nodeId` 修掉 error，再处理高影响 warn。详见 `references/audit.md`。
- 用 `figma_screenshot` 在目标视口看当前屏；不要只看代码或缩略图。
- 至少检查：目标视口 100%、关键区域 200%、首屏缩到 480px 宽的三秒测试。
- 有文本节点时检查：字号、行高、中文断行、截断/溢出、长内容；有状态/交互时检查操作后状态。
- 截图保存成功不等于看过；交付前必须真的读图。

### 6. 独立评审

新界面/整体改版做完代表页面后，派一个**没有制作历史的子 Agent**做评审。给它：

- 当前截图（目标视口，必要时 480px 缩略图和 200% 局部）；
- 用户原始任务、设计约束、北极星一句；
- `references/reviewer.md` 的路径。

**不要给**：源代码、制作过程、你的推荐或辩护、上一轮评分。

评审返回 1–10 分、按影响排序的问题清单、一条“保留什么”。按清单修改；第一条是“重做”时回方向卡重做骨架，不逐条修补。改完做一轮复核，不无限循环。

没有可看图的隔离执行者时，自己按 `references/reviewer.md` 自查，并在交付说明写“未独立评审”。

### 7. 交付

交付说明写清：选定方向与理由、改了什么/没做什么、用了哪些设计系统对象、证据截图路径、独立评审分数与处理结果。把 `DESIGN.md` 和评审记录留在任务目录，不写进插件安装目录。

## 硬规则

- 一屏一个主角、一个主动作；删掉不服务任务的元素再谈美化。
- 先结构后视觉；先灰度后颜色。
- 已有品牌、字体、主色、组件优先；不为了“新”另造设计系统。
- 真实内容、真实数据、真实状态；不伪造成功/评价/指标。
- 没有真实截图，不声称视觉通过；没有实际交互，不声称动效通过。
- 不用“高级/精致/克制”当设计理由；说清具体数值和关系。
