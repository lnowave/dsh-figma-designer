# figma-design

操作 Figma 用 `figma-designer` skill（status/read/apply/screenshot/library/...）。本 skill 只管设计判断、约束和验收。

## 先选档位

**快速（默认）**：单屏或简单页面、内容已明确、不需要多方向比较。
→ 直接做，不写 `DESIGN.md`、不单独做灰度稿、不派独立评审。

**打磨**：用户说“打磨/评审/做几个方向/像真实产品”，或这是有商业分量的核心页面。
→ 走下面的完整流程。

## 快速路径

> 预算：简单页面 ≤6 次工具调用（status / library / read / apply / screenshot 各 1–2 次），≤2 张截图。超出说明在做打磨档的事。

1. **一句话约束**：谁用、主任务、主视口、真实内容、有没有现成设计系统。能读 Figma 就 `figma_designer_library` 看一眼；读不到的合理默认自己定，**不要为此多轮确认**。
2. **一次成型**：结构与视觉在同一次 `figma_designer_apply` 里完成。
   - 一屏一个主角、一个主动作；层级清楚、真实文案、不留占位符。
   - 字号梯度 ≤4 级，颜色 ≤6 个，间距走 4/8 的倍数，圆角同类统一。
   - 整页用一个带 Auto Layout 的 frame 组织，不要几十个散层。
3. **一张截图 → 最多修一轮**：`figma_designer_screenshot`（大画板 `scale:0.5–0.75`），只修看得见的明显问题（错位、溢出、对比度、层级）。修完再截一次即止。
4. **交付**：一句话说方向与取舍，附截图路径。

## 打磨路径

1. **事实与范围**：用户、产品、核心任务、真实内容、目标设备、现有设计系统、参考与限制。只问会改变方向且推断不出的问题。
2. **方向卡**：写 `DESIGN.md`（模板 `references/design-doc-template.md`）：北极星、主角/主动作、调性五刻度、字体色彩间距圆角、页面骨架、记忆点、主动放弃什么。默认只做一个方向；用户要比较才做 2–3 个首屏。
3. **灰度结构**：先只做灰阶层级与主动作，截图确认结构；用户说“你定/直接做”时不停顿，但仍按顺序。
4. **设计系统与视觉**：优先复用 `figma_designer_library` 的组件/变量/样式；没有就用 `figma_designer_variable`/`figma_designer_style` 建最小集。视觉语言见 `references/visual-language.md`，token 配方见 `references/tokens.md`。真实内容优先，避免紫蓝弥散光、玻璃卡片、千篇一律的 SaaS 卡片墙。
5. **证据**：`figma_designer_audit` 跑一次，按 `nodeId` 修 error 和高影响 warn（`references/audit.md`）；目标视口截图一张；只有怀疑字体/对齐/裁切时才加 200% 局部。
6. **独立评审**：派一个没有制作历史的子 Agent，给当前截图、用户原始任务、北极星一句、`references/reviewer.md` 路径；不给源码、过程和你的辩护。按返回的 1–10 分和影响排序清单改**一轮**，第一条是“重做”才回方向卡，不无限循环。
7. **交付**：方向与理由、改了什么/没做什么、用了哪些设计系统对象、证据截图、评审分数与处理结果。`DESIGN.md` 与评审记录留在任务目录。

## 证据预算（避免把简单页面做成一小时）

- 每轮改动只截 1 张；整页设计最多 3 张（结构、视觉、终验）。
- `figma_designer_audit` 交付前跑一次即可，不要每轮跑。
- 不要重复读整页、不要为同一批改动反复 `dryRun`。
- 截图能看出问题时直接改，不要为了“更稳妥”再加一轮全量检查。

## 硬规则

- 一屏一个主角、一个主动作；先删不服务任务的元素，再谈美化。
- 先结构后视觉；快速路径可以一次成型，但心里先有结构。
- 已有品牌、字体、主色、组件优先，不为“新”另造设计系统。
- 真实内容、真实数据、真实状态；不伪造成功/评价/指标。
- 没有真实截图不声称视觉通过；没有实际交互不声称动效通过。
- 不用“高级/精致/克制”当理由，说清具体数值和关系。
